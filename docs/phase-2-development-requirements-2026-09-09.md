## 1. 背景与目标

第一期已经完成评级语义拆分、证据门禁、时点约束、基本面预测/估值/评级的确定性计算、短期预测和校准的安全降级、模型治理及跨市场隔离。第二期不重复这些模块，目标是补齐原任务清单中尚未通过真实数据验收的十项能力：`P1-09`、`P2-01` 至 `P2-07`、`P3-01`、`P3-02`。

第二期必须形成以下闭环：

1. 无新闻时也能基于当时可用的财务、价格、基准和已批准假设触发基本面复核。
2. 行情、公司行动、基准和历史证券池形成不可变、可追溯的真值层。
3. 训练、校准和未来测试严格按时间与事件簇隔离。
4. 只有真实独立样本通过门禁后才发布概率或切换模型。
5. 反方研究和新增资产模型必须用消融或分市场报告证明价值，不能用 Agent 数量或开发完成度代替效果证据。

## 2. 强制约束

- 第一方生产运行时保持 Go，未经单独架构批准不得引入 Python 服务、依赖清单或镜像。
- 缺失价格、基准、公司行动、财务、假设、模型或校准器时返回明确不可用状态，禁止写入零值或估算值冒充事实。
- 所有行情和财务记录必须保存 `observed_at`、`available_at`、来源、币种、字段口径和原始身份。
- 训练样本只能使用训练截止时已经成熟且可获得的标签；同一事件及转载簇不得跨越训练、校准和测试集合。
- 模型、校准器和评级切换必须经过 Shadow、正确性硬门禁和人工批准；漂移只能触发告警与复核。
- 每个步骤必须通过相关单元测试、PostgreSQL 集成测试、Go CI；涉及前端时还需通过 Vitest 和生产构建。
- 每个可交付步骤独立提交、推送到 `origin/golang`，并按仓库发布规范部署和读回验证。

## 3. 开发里程碑

### M1：真实数据基础与自动基本面复核

#### M1.1 不可变行情观测

- 建立价格观测表，区分 `close` 与 `adjusted_close`。
- 保存交易日、实际观测时间、系统可获得时间、币种、来源和日线/时间戳精度。
- 现有结果计算从真实供应商取得价格后同步写入该表；同一来源记录必须幂等。
- 禁止将普通收盘价静默标记为复权价。

验收：重复抓取不产生重复记录；未来可获得的价格不会进入历史截止时间；基准价格使用同一契约。

#### M1.2 公司行动、基准和历史证券池

- 增加拆股、分红、合股、代码变化、停牌和退市事件契约。
- 保存历史证券有效区间和基准映射，不能用当前成分覆盖过去。
- 数据质量报告披露缺失、降级、排除和来源冲突。

验收：拆股与分红样例不会产生虚假收益；缺失基准时相对收益保持不可用。

#### M1.3 无新闻定时基本面研究

- 只选择已跟踪、策略支持且输入完整的标的。
- 财务刷新后比较最新可用快照与上一研究版本；无变化时不重复计算。
- 新估值必须使用可追溯的当前价格、基准和显式批准的假设/情景。
- 输入不完整时记录结构化阻断原因，不创建虚假评级修订。

验收：手动和定时入口对同一输入产生相同版本；任务幂等；失败可重试且不会覆盖历史评级。

### M2：真实结果标签与数据质量

- 实现 1、5、20 个交易日独立成熟标签。
- 从 `signal_available_at` 后第一个可交易时点取价。
- 分开保存绝对收益、基准收益、超额收益和配置成本后的模拟净收益。
- 建立行情覆盖、公司行动覆盖、基准覆盖、退市样本和失败样本报告。

验收：盘后、周末、停牌、拆股、分红、退市和跨市场样例全部通过；未到期样本不提前评价。

### M3：滚动前推数据集

- 生成不可变数据集清单，保存样本、版本、排除原因和特征截止时间。
- 多轮划分训练、独立校准和未来测试窗口。
- 按事件/转载簇隔离，并根据标签期限清除跨边界重叠。
- 最终留出集不能被自动演进或日常调参读取。

验收：任一训练标签在训练截止时已成熟；数据集可完全重现；泄漏测试能主动拦截污染样本。

### M4：可解释基线与独立校准

- 比较恒定基线、简单规则、现有方向分和可解释线性/逻辑模型。
- 分别消融价格、基本面、新闻和预期修订特征。
- 校准样本与训练样本隔离，按资产类别、市场和期限限定适用范围。
- 样本不足、范围不符或校准过期时继续返回 `uncalibrated`。

验收：未来样本报告优于或明确不优于简单基线；制品、预处理和校准版本可复现。

### M5：分层报告、Shadow 与故障演练

- 分开报告研究质量、预测能力、覆盖率和可执行模拟结果。
- 披露拒答、看空、未到期、缺数据、技术失败和退市样本。
- 正式/候选模型以相同截止和执行假设并行运行。
- 演练数据源失效、模型超时、分布漂移、校准失效和人工回滚。

验收：所有告警、批准和回滚均有持久审计；开发集提升不能自动触发上线。

### M6：可选增强验收

- 反方研究先以关闭状态积累人工标签，报告错误发现率、误挑战、延迟和成本；无稳定增量价值则保持关闭。
- 新资产按 ETF、加密资产、商品顺序逐类实现，每类使用独立数据、政策、基准、日历和效果报告。
- 不支持的基本面方法继续返回 `not_applicable`。

## 5. 第二期完成定义

第二期只有在以下条件全部满足后才能标记完成：

- M1 至 M5 的代码、调用链、数据库迁移、自动化测试和生产读回全部通过。
- 已使用真实生产来源形成可审计的 PIT 数据集和成熟标签。
- 至少一个股票市场完成滚动训练、独立校准和从未参与选择的未来留出测试。
- 效果报告同时披露覆盖率、失败样本和统计不确定性，而非只报告成功预测。
- 模型切换和回滚演练完成，且没有未经人工批准的自动上线路径。
- M6 仍为可选增强；未证明增量价值的功能可以保持关闭或不适用，但必须明确记录原因。

## 6. 交付记录

### 2.1 第二期需求冻结与不可变行情观测

- 新增 `market_price_observations`，不可变保存资产、市场、币种、交易日、观测时间、首次可获得时间、价格字段、时间精度和来源身份。
- `close` 与 `adjusted_close` 使用不同身份，普通收盘价不能冒充复权价。
- 现有真实结果任务从 FMP、Market Adapter 或 CoinGecko 取得资产及基准价格后，将标准化结果幂等写入真值表。
- 重复抓取保留第一次 `available_at`，避免后来补采的数据伪装成历史时点已经可用。
- 本步骤只建立行情真值基础，不宣称公司行动、历史证券池或自动估值已经完成。
