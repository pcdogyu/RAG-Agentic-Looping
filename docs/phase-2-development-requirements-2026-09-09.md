# RAG-Agentic-Looping 第二期开发需求

版本：2.0

日期：2026-09-09

目标分支：`golang`
基线提交：`ac052c62af93e2943e6f2eb19669adb0e55f9825`

## 1. 背景与目标

第一期已经完成评级语义拆分、证据门禁、时点约束、基本面预测/估值/评级的确定性计算、短期预测和校准的安全降级、模型治理及跨市场隔离。第二期不重复这些模块，目标是补齐原任务清单中尚未通过真实数据验收的十项能力：`P1-09`、`P2-01` 至 `P2-07`、`P3-01`、`P3-02`。

第二期必须形成以下闭环：

1. 无新闻时也能基于当时可用的财务、价格、基准和已批准假设触发基本面复核。
2. 行情、公司行动、基准和历史证券池形成不可变、可追溯的真值层。
3. 训练、校准和未来测试严格按时间与事件簇隔离。
4. 只有真实独立样本通过门禁后才发布概率或切换模型。
5. 反方研究和新增资产模型必须用消融或分市场报告证明价值，不能用 Agent 数量或开发完成度代替效果证据。

## 2. 强制约束

- 第一方生产运行时保持 Go，未经单独架构批准不得引入 Python 服务、依赖清单或镜像。
- 缺失价格、基准、公司行动、财务、假设、模型或校准器时返回明确不可用状态，禁止写入零值或估算值冒充事实。
- 所有行情和财务记录必须保存 `observed_at`、`available_at`、来源、币种、字段口径和原始身份。
- 训练样本只能使用训练截止时已经成熟且可获得的标签；同一事件及转载簇不得跨越训练、校准和测试集合。
- 模型、校准器和评级切换必须经过 Shadow、正确性硬门禁和人工批准；漂移只能触发告警与复核。
- 每个步骤必须通过相关单元测试、PostgreSQL 集成测试、Go CI；涉及前端时还需通过 Vitest 和生产构建。
- 每个可交付步骤独立提交、推送到 `origin/golang`，并按仓库发布规范部署和读回验证。

## 3. 开发里程碑

### M1：真实数据基础与自动基本面复核

#### M1.1 不可变行情观测

- 建立价格观测表，区分 `close` 与 `adjusted_close`。
- 保存交易日、实际观测时间、系统可获得时间、币种、来源和日线/时间戳精度。
- 现有结果计算从真实供应商取得价格后同步写入该表；同一来源记录必须幂等。
- 禁止将普通收盘价静默标记为复权价。

验收：重复抓取不产生重复记录；未来可获得的价格不会进入历史截止时间；基准价格使用同一契约。

#### M1.2 公司行动、基准和历史证券池

- 增加拆股、分红、合股、代码变化、停牌和退市事件契约。
- 保存历史证券有效区间和基准映射，不能用当前成分覆盖过去。
- 数据质量报告披露缺失、降级、排除和来源冲突。

验收：拆股与分红样例不会产生虚假收益；缺失基准时相对收益保持不可用。

#### M1.3 无新闻定时基本面研究

- 只选择已跟踪、策略支持且输入完整的标的。
- 财务刷新后比较最新可用快照与上一研究版本；无变化时不重复计算。
- 新估值必须使用可追溯的当前价格、基准和显式批准的假设/情景。
- 输入不完整时记录结构化阻断原因，不创建虚假评级修订。

验收：手动和定时入口对同一输入产生相同版本；任务幂等；失败可重试且不会覆盖历史评级。

### M2：真实结果标签与数据质量

- 实现 1、5、20 个交易日独立成熟标签。
- 从 `signal_available_at` 后第一个可交易时点取价。
- 分开保存绝对收益、基准收益、超额收益和配置成本后的模拟净收益。
- 建立行情覆盖、公司行动覆盖、基准覆盖、退市样本和失败样本报告。

验收：盘后、周末、停牌、拆股、分红、退市和跨市场样例全部通过；未到期样本不提前评价。

### M3：滚动前推数据集

- 生成不可变数据集清单，保存样本、版本、排除原因和特征截止时间。
- 多轮划分训练、独立校准和未来测试窗口。
- 按事件/转载簇隔离，并根据标签期限清除跨边界重叠。
- 最终留出集不能被自动演进或日常调参读取。

验收：任一训练标签在训练截止时已成熟；数据集可完全重现；泄漏测试能主动拦截污染样本。

### M4：可解释基线与独立校准

- 比较恒定基线、简单规则、现有方向分和可解释线性/逻辑模型。
- 分别消融价格、基本面、新闻和预期修订特征。
- 校准样本与训练样本隔离，按资产类别、市场和期限限定适用范围。
- 样本不足、范围不符或校准过期时继续返回 `uncalibrated`。

验收：未来样本报告优于或明确不优于简单基线；制品、预处理和校准版本可复现。

### M5：分层报告、Shadow 与故障演练

- 分开报告研究质量、预测能力、覆盖率和可执行模拟结果。
- 披露拒答、看空、未到期、缺数据、技术失败和退市样本。
- 正式/候选模型以相同截止和执行假设并行运行。
- 演练数据源失效、模型超时、分布漂移、校准失效和人工回滚。

验收：所有告警、批准和回滚均有持久审计；开发集提升不能自动触发上线。

### M6：可选增强验收

- 反方研究先以关闭状态积累人工标签，报告错误发现率、误挑战、延迟和成本；无稳定增量价值则保持关闭。
- 新资产按 ETF、加密资产、商品顺序逐类实现，每类使用独立数据、政策、基准、日历和效果报告。
- 不支持的基本面方法继续返回 `not_applicable`。

## 6. 交付记录

### 2.1 第二期需求冻结与不可变行情观测

- 新增 `market_price_observations`，不可变保存资产、市场、币种、交易日、观测时间、首次可获得时间、价格字段、时间精度和来源身份。
- `close` 与 `adjusted_close` 使用不同身份，普通收盘价不能冒充复权价。
- 现有真实结果任务从 FMP、Market Adapter 或 CoinGecko 取得资产及基准价格后，将标准化结果幂等写入真值表。
- 重复抓取保留第一次 `available_at`，避免后来补采的数据伪装成历史时点已经可用。
- `GET /go/market-prices/{assetID}` 分开接受价格观测截止和系统可获得截止；查询会选择当时已经可用的最新供应商修订。
- 本步骤只建立行情真值基础，不宣称公司行动、历史证券池或自动估值已经完成。

### 2.2a 公司行动真值层

- 新增 `corporate_action_observations`，覆盖现金分红、拆股、合股、代码变化、停牌和退市，并分别保存生效、观测、首次可获得、公告、登记、支付和结束时间。
- 供应商同一事件的后续修订保留为新记录；时点查询只返回截止时已经可获得的最新修订，后补历史数据不会泄漏到过去。
- FMP `/dividends` 与 `/splits` 已接入主数据 Worker；手工同步使用 `POST /go/corporate-actions/{assetID}/sync`，定时基本面刷新也同步对应公司行动。
- `GET /go/corporate-actions/{assetID}` 支持分别指定生效截止、系统可获得截止和事件类型。
- 普通拆股与合股由比例方向严格区分，现金分红同时保留原始和供应商复权金额；来源 URL 会去除凭据。
- 本子步骤仅交付公司行动；基准映射和历史证券池由后续 2.2b 独立交付。

### 2.2b 时点基准映射、历史证券池与质量披露

- 新增 `benchmark_mapping_observations`，按资产、行业、市场或策略保存不可变基准政策；每条记录包含精确基准资产 ID、双方市场与币种、有效区间、首次可获得时间、来源、理由和审批人。
- 管理员通过 `POST /go/benchmark-mappings` 显式批准映射，请求必须携带幂等键；跨币种映射、基准资产不存在、资产自我基准和身份不一致会被拒绝。迁移不自动填入任何猜测或倒填的历史策略。
- `GET /go/benchmark-mappings/{assetID}` 按有效时点和可获得截止解析优先级；历史行业只能由调用方提供当时的行业上下文，禁止读取今天的行业分类替代过去。
- 结果计算已移除按市场写死的 SPY、沪深 300、恒指和 BTC 路径。信号产生时尚未批准映射、精确身份/币种不完整或基准价格缺失时，`benchmark_return` 与 `alpha` 保持空值，并记录结构化 `unavailable` 原因。
- 旧版硬编码路径已经生成的相对收益不会继续冒充已批准结果：迁移将原值保存在 `legacy_benchmark_audit`，公开字段置空并标记 `legacy_unapproved_mapping`；绝对收益仍保留。
- 新增 `security_universe_snapshots` 与 `security_universe_memberships`。每次主数据刷新不可变保存供应商、纳入条件、纳入、排除、供应商明确退市和失败状态；供应商列表缺失只标记为排除，不推断为退市，失败刷新不清空现有证券。
- `GET /go/security-universes/{universeID}/snapshots` 和 `GET /go/security-universe-memberships/{assetID}` 支持按可获得时点读回历史；`GET /go/market-data-quality` 汇总基准缺失、证券池失败/排除/退市、行情和公司行动覆盖，并公开各类缺失处理规则。
- PostgreSQL 回归测试覆盖事后批准不回灌、幂等审批、币种冲突、失败快照、未来快照隔离，以及纳入/排除/退市三类成员记录。

### 2.3 无新闻定时基本面研究

- 管理员通过 `PUT /go/fundamental-research/{assetID}/schedule` 显式批准不可变计划版本；请求必须携带幂等键，并绑定已经存在的可用预测版本、证据化估值情景和评级政策。
- 调度器每小时检查到期计划，单次最多处理 10 个标的；每个计划按自己的 cadence 决定实际运行时间。
- 到期运行先刷新 FMP 财务快照和真实价格观测，再以最新可用复权价重算估值与评级；不自动创造或修改财务假设。
- 若预测版本之后出现新财报、计划过期、复权价缺失或过期，则返回明确状态；新财报和计划过期会将计划转为 `review_required`。
- 相同预测、计划和价格时点产生相同估值/评级身份，重试不追加重复评级修订；数据刷新或技术失败最多一小时后重试。
- `GET /go/fundamental-research/{assetID}/schedule` 查看完整计划历史，`DELETE` 由管理员暂停当前计划；前端“基本面与预测”页提供批准、状态查看和暂停入口。
- PostgreSQL 端到端回归以同一财务快照、预测输入、估值情景、价格证据、基准证据、评级政策和有效时点分别执行定时与手动入口，并断言复用同一个预测版本、估值版本和评级修订；入口来源标签不进入计算身份，也不会制造重复评级历史。

### 2.4 多期限真实结果标签与质量报告

- 冻结 `prediction-outcome-label-v1`，只接受 `absolute_up` / `excess_up` 与 1、5、20 个交易日；中性区间、入退出、复权价格和 alpha 算术定义均在观察未来结果前固定。
- outcomes Worker 已接通 `prediction_runs → outcome_records`：各期限独立成熟，未成熟记录保持 pending；未预注册 v1 的旧预测、预测无分数、口径不支持和资产类别未实现分别保存为 excluded。
- 股票只接受供应商明确标记的 `adjusted_close`。信号后第一个可观测交易日入场，入场后第 N 个可观测交易日退出；周末、节假日、停牌和历史补采不会按自然日提前成熟。
- 相对目标只使用信号时已经批准的精确基准映射，且要求同币种、相同入退出交易日期；缺基准或基准缺日时保留绝对研究结果，但相对目标标记 unavailable。
- 分开保存 `raw_return`、`benchmark_return`、`excess_return`、风险调整残差状态和模拟净收益。没有模型注册时预存的执行成本/滑点/资金费用时，`net_return` 为空且明确标记 `research_result_only`。
- `GET /go/outcome-labels/{assetID}` 读回完整标签历史；市场数据质量接口增加 mature、pending、unavailable、excluded 标签计数。
- 口径详见 `docs/outcome-label-definition-v1.md`；单元回归覆盖绝对上涨但相对落后、1/5/20 独立成熟、盘后/周末和迟到补采，PostgreSQL 端到端回归覆盖 Worker 幂等写入。

### 2.5 滚动前推数据集与泄漏门禁

- 新增 `walk-forward-dataset-v1`：训练窗口按固定长度真实滚动，校准和未来测试使用独立时间窗口，分区之间设置显式 embargo。
- 每个样本都校验特征截止、预测创建时间、标签入退出窗口和标签可获得时间；标签窗口跨越分区边界或在该轮截止时尚未成熟会被排除，embargo 不替代逐样本 PIT 检查。
- 事件 ID 与转载簇按传递闭包隔离；同一事实不能跨训练、校准、测试或最终留出集，所有排除项保存结构化原因。
- 新增管理员限定的最终留出集预注册接口。预留必须发生在首个信号前，目标、期限、区间、标签截止和批准人冻结；密封样本不通过 API 暴露给日常调参或自动模型选择。
- 新增数据集版本、折次、样本清单和密封留出样本四类持久化表；内容摘要、幂等键、折次边界、完整开发样本时点和排除原因可读回复现。
- 没有合格最终留出样本时拒绝构建。生产环境若尚无模型、预测和成熟标签，只代表能力已部署，不代表真实数据验收或最终留出评测已完成。
- 完整契约与接口见 `docs/walk-forward-dataset-contract-v1.md`；单元回归覆盖滚动窗口、逆序输入复现、未来特征、事后预测、标签跨界、传递转载簇和密封留出，PostgreSQL 回归覆盖迁移、幂等持久化与 API 清单脱敏。

### 2.6 可解释基线、消融和独立校准

- 新增 `baseline-calibration-experiment-v1`，按每个滚动折次分别读取训练、独立校准和未来测试分区；SQL 固定排除 `sealed=true` 及负折次，最终留出集不能进入开发实验。
- 同口径比较历史正类率、简单规则、LLM 方向分、可解释逻辑回归以及价格、基本面、新闻、预期修订四组消融。LLM 分数或完整特征缺失时明确标记不可用，不把缺失填零。
- 所有逻辑回归和消融在完整全特征的共同样本上运行；均值、尺度、系数与模型版本只由当轮训练样本产生，未来测试结果不会反向进入预处理或拟合。
- 二分类模型使用独立 calibration 分区拟合 Platt 校准器，至少要求 30 个独立事件簇和正负两类；资产类别、市场、期限、模型版本、时间范围或有效期不匹配时保持 `uncalibrated`。
- 未来 test 分区报告 accuracy、正类率、预测偏斜、Rank IC、Brier、log loss、ECE、可靠性分箱及每箱 Wilson 95% 区间；逐样本分数、概率、标签和收益可追溯。
- 实验制品、模型预处理、校准器、消融差异和机器可读报告均不可变持久化，幂等键不能绑定不同实验；实验不会自动注册、批准或替换生产模型。
- 完整口径见 `docs/baseline-calibration-experiment-v1.md`。生产尚无模型、数据集和成熟标签时，只能确认能力已部署，不能声称真实基线优于简单规则或概率已经通过市场验收。

### 2.7 分层效果报告、Shadow 和故障演练

- 新增 `layered-performance-report-v1`，将研究质量、信号预测与可执行模拟严格分层；事实、关系、引用支持和拒答合理性使用不可变人工逐维标签计算准确率与区间，缺标签保持不可用；覆盖率和准确率同时披露，看空/非看多与看多方向分别报告绝对和超额收益。
- 信号结果按独立事件簇和时间折次报告，不汇总伪独立显著性；accuracy 带 Wilson 95% 区间，小样本明确警告，概率校准与方向/收益指标保持不同字段。
- 数据质量公开候选、排除/拒绝、未成熟、缺失、技术失败和全部排除原因；报告可定位数据集、实验、逐样本结果及制品版本，但不暴露密封最终留出样本 ID。
- 没有显式成本时净收益保持空值；没有组合权重、仓位和权益曲线时换手、敞口和策略回撤保持不可用，禁止使用资产回撤替代。
- 模型注册时在不可变范围中预注册独立样本、Shadow 周期、最大 ECE 和回滚触发条件；晋升请求不能事后降低门槛。候选晋升后同资产类别/目标/市场/期限的旧正式模型转为 `superseded`；新增显式人工回滚接口，只允许恢复同范围、曾经获批的版本，全部切换写入持久治理审计。
- 新增五类非生产变更故障演练：数据源不可用、模型超时、特征分布漂移、校准过期和人工回滚门禁。数据库约束禁止演练修改生产状态；漂移、超时和质量下降只能告警、降级或要求人工回滚。
- 完整契约与接口见 `docs/layered-performance-and-governance-v1.md`。开发报告提升仍不能自动上线；真实前瞻样本、成熟结果、生产告警与持续演练必须另行积累。

### 2.8 反方研究与新增资产模型验收

- 反方研究继续默认关闭。反证必须精确关联核心 claim，使用截止时可得、首轮未引用且底层来源独立的证据；候选错误不改写主报告或置信度。
- 消融入口要求唯一事件簇、相同输入截止、固定新旧版本、时间折次和独立真值来源；报告错误发现率、误挑战率及 Wilson 95% 区间，同时披露额外延迟、成本和逐折稳定性。
- 少于 100 个独立复核、20 个 baseline 错误、三个稳定时间折次，或统计区间未过门槛时保持 `keep_disabled`；达标也只进入人工复核，不能自动开启。
- `market-policy-v3` 分别冻结股票、ETF、加密资产和商品的币种、时区、日历、时点基准政策、专用研究输入及执行约束；不适用的股票式财务方法保持 `not_applicable`。
- 新增数据库驱动的分市场就绪报告，按 `asset_class:market` 披露资产、模型、预测、同范围校准和成熟结果；先要求至少一个股票市场完成端到端前瞻验收，再允许 ETF、加密或商品进入人工验收判断。
- 完整契约见 `docs/optional-counter-research-and-market-readiness-v1.md`。生产没有合格模型和成熟样本时，新增资产效果仍是不可用，不以开发完成度冒充增量价值。

### 2.9 真实生产数据冷启动

- 每日事实数据刷新除显式预测/评级标的外，允许纳入最近 30 天由当前 `llm-direction-v3` 证据契约完成研究的美股标的，打破“先有预测/评级才同步财务”的循环依赖。
- 冷启动仅同步 FMP 财务快照和公司行动；旧评分版本、过期研究、非美股和非股票资产不能借此进入当前基本面流程。
- 结果记录 `recent-research-fundamental-bootstrap-v1` 选择策略及逐标的选择原因，并明确 `automatic_assumptions=false`、`automatic_ratings=false`、`automatic_predictions=false`。
- 这一步不把旧推荐评分当作收益标签，不注册伪造样本的模型，也不发布未校准概率。显式财务假设、估值情景、基准和评级政策仍需由分析师批准；真实预测和成熟结果仍按时间自然积累。
- PostgreSQL 隔离回归覆盖显式跟踪优先、当前契约近期研究准入，以及旧契约、过期研究和跨市场标的排除。

### 2.10 前瞻规则基线样本采集

- 新的 `llm-direction-v3` 推荐与一项 outcomes 采集任务在同一事务中写入，避免研究成功但样本采集任务丢失；任务只处理自身绑定的新推荐，不扫描或倒填已经看到结果的历史推荐。
- 单并发研究 Worker 使用完成优先队列：已由事件阶段产生的标的研究先于新的上游事件研究执行，其中可进入本阶段前瞻采集的 NASDAQ、NYSE、AMEX 标的优先；其他市场的标的研究随后继续执行，不删除或跳过。该顺序避免事件积压及跨市场积压使推荐、预测与结果链路长期饥饿；双并发时仍保留 fast/preferred 分工。
- 为美股分别冻结 1、5、20 个交易日的 `llm_direction_score` 恒等规则基线。它保留原始大模型方向分作为 `raw_score`，`sample_count=0`，不声称经过训练，也不输出概率。
- 规则基线永久标记为 `forward_data_collection_only`、`promotion_eligible=false`；模型晋升接口返回 `fixed_rule_data_collection_only`，校准注册接口也拒绝把该采集基线包装成已校准概率。
- 预测记录保留推荐 ID 作为特征来源，并沿用原始 `signal_available_at`。重复任务使用同一预测身份；早于该基线首次有效时间的信号被跳过，不能事后回填。
- PostgreSQL 端到端回归验证三期限建模、预测写入、无概率、任务幂等、历史信号拒绝和晋升阻断。真实成熟标签仍需等待未来 1、5、20 个交易日，并继续遵循行情、公司行动和基准质量门禁。

### 2.11 无新闻基本面人工准备包

- 新增 `GET /go/fundamental-research/{assetID}/preparation`，只从请求截止时已经可用、报告期和期间类型完全一致的利润表、资产负债表和现金流量表构建只读准备包；禁止混用不同报告期凑齐输入。
- 准备包从原始财务事实推导收入、营业利润率、实际税率、折旧摊销、资本开支、营运资金变化和稀释股数，并对每个字段保存快照 ID、原始指标和值及计算变换。资本开支统一为正的现金流出，供应商现金流表中的营运资金符号显式反转。
- 缺少任一事实时对应字段保持 `null` 并返回 `missing_fields`，不以零填充；截止时间之后的财报修订不会进入准备包。
- 页面可将准备包载入无新闻研究 JSON 编辑器，但估值情景、资本成本或可比公司证据、基准预期、原因码、失效规则和批准人仍保持人工输入。响应明确声明不自动生成假设、估值或评级。
- PostgreSQL 隔离回归覆盖同报告期选择、未来修订隔离、比例推导、现金流符号标准化、字段级来源，以及未产生任何受治理输入或批准状态。

### 2.12 一致预期首次观测与前瞻修订历史

- 新增 FMP `analyst-estimates` 年度一致预期适配器，采集收入、EPS、EBITDA、EBIT、净利润和销售管理费用的 low、mean、high，以及供应商提供的收入/EPS 分析师样本数；期间、币种、统计方式、口径和来源记录分开保存。
- FMP 当前接口不提供预测的发布或修订时间，因此系统把本地抓取时点明确记录为 `first_observed_at`，响应和原始载荷均声明 `provider_publication_time_available=false`、`historical_backfill=false`。不得将首次抓到的当前值伪装成公告前历史预期。
- 新增管理员接口 `POST /go/consensus/{assetID}/sync` 和只读接口 `GET /go/consensus/{assetID}`；只读查询严格应用 `as_of` 截止，首次观测前返回空列表。
- 每日受跟踪/近期完成研究的美股事实刷新同时采集一致预期，从上线日起前瞻积累真实修订序列。管理层指引继续与一致预期分表，并只接受带来源、适用期间和真实发布时间的管理员导入。
- 同一期间的供应商原始汇总记录未变化时不追加重复快照；任一字段变化时按新的首次观测时点保存整条汇总记录对应的指标范围，以便复原每次真实修订的覆盖范围。
- 一致预期采集只写事实快照，不生成预测假设、估值或基本面评级。PostgreSQL 隔离回归验证首次观测时间、未来数据隔离、完整来源、无历史倒填和无评级副作用。

### 2.13 公告语义与管理层指引修订

- 新增 `announcement-expectation-semantics-v1`，将同比变化与公告前一致预期偏差分开计算和返回；能够分别表达 `growth_below_consensus` 与 `decline_above_consensus`，不再把业务增长和市场超预期混为一个方向。
- 同比要求资产、指标、期间类型、币种、单位和会计口径一致，并要求可比较的上年同期；上期值小于或等于零时只保留绝对变化，简单百分比明确为 `unavailable_non_positive_prior`。
- `POST /go/consensus/{assetID}/announcement-assessment` 只读取严格早于公告时点的一致预期；期间、币种、单位或 GAAP/非 GAAP 口径不一致时保持 unavailable，不降级为猜测。
- 一致预期只从供应商汇总快照计算修订方向、绝对幅度和样本数变化，并明确 `individual_analyst_behavior_status=unavailable_aggregate_snapshots_only`，不得推断单个分析师行为。
- `GET /go/consensus/{assetID}/guidance` 按可用时点读回管理层指引旧值、新值、区间、适用期间和来源，并计算上调/下调、区间收窄/扩大及变动边界；响应明确 `guidance_is_consensus=false`。
- PostgreSQL 隔离回归覆盖指引修订前截止、旧/新区间持久化和修订方向；单元回归覆盖“同比增长但低于预期”“同比下降但好于预期”、非正上期值以及聚合预期修订边界。

### 2.14 SEC 原始披露候选与管理层指引人工确认

- 新增 SEC EDGAR 官方披露适配器。它先从官方公司代码目录解析 CIK，再读取公司 submissions JSON，只把 `8-K`、`10-Q`、`10-K`、`6-K`、`20-F`、`40-F` 及其修订表单保存为“可能含指引的待核验文档”；遵循 SEC 自动访问要求并强制配置可识别的 `SEC_IDENTITY`，无身份时明确不可用。
- `guidance_source_documents` 不可变保存 CIK、accession number、表单、报告日、申报日、SEC 接收时间、首次本地观测时间、申报索引页、主文档和原始元数据。SEC 明确说明接收时间到网页可访问通常仍有 1—3 分钟且不保证，因此 `accepted_at` 保留官方时间，`source_available_at` 保守使用首次本地观测时间；历史截止早于首次观测时文档不可见，不做事后倒填。
- 文档候选明确标记 `candidate_is_guidance=false`、`automatic_extraction=false`。发现财报或 8-K 不会自动生成指引、假设、评级或概率，也不会把申报表中的任意前瞻叙述猜成数值区间。
- `GET /go/consensus/{assetID}/guidance-sources` 按时点返回候选和最新人工核验状态；`POST .../guidance-sources/sync` 仅排队官方文档同步；`POST .../guidance-sources/{documentID}/reviews` 保存幂等的 `confirmed_guidance`、`no_guidance` 或 `needs_follow_up` 审核。
- 只有 `confirmed_guidance` 且人工提供适用期间、指标、币种、单位、会计口径、原文摘录、披露位置、同一 accession 目录中的证据 URL 和审核人时，才在同一数据库事务内生成管理层指引快照。`published_at` 和来源身份由 SEC 候选强制覆盖客户端值，`available_at` 使用人工核验完成时间；事后人工提取不会回灌到核验前的历史回放。
- 每日受跟踪美股事实刷新在 SEC 身份已配置时同步披露候选；身份缺失只报告 `sec_identity_not_configured`，不影响已有财务、一致预期和公司行动刷新。生产当前尚未配置 SEC 身份，因此真实候选数和人工确认数仍必须保持为零/不可用，不能据此声称 P1-02 已通过真实指引历史验收。
- 单元回归覆盖 User-Agent、CIK 解析、平行数组完整性、支持表单、官方时间语义和跨 accession 证据 URL 拒绝；PostgreSQL 回归覆盖候选幂等、公告前截止、人工确认、来源字段强制覆盖、核验幂等冲突以及无评级副作用。

官方数据契约参考：[SEC EDGAR 数据 API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) 与 [SEC EDGAR 访问说明](https://www.sec.gov/search-filings/edgar-search-assistance)。

### 2.15 无新闻研究真实复权价格冷启动

- 新增管理员限定的 `POST /go/market-prices/{assetID}/sync`，把单标的最近 1—90 日真实供应商行情排入主数据 Worker；默认同步最近 14 日。它与定时研究和真实结果标签复用同一价格适配器、标准化逻辑与 `market_price_observations` 不可变存储，不建立第二套价格口径。
- 同步结果分别报告供应商返回数、复权收盘价数、新增数和累计数；没有可靠 `adjusted_close` 时返回明确 `unavailable`，普通收盘价不能冒充复权价格证据。
- 同步只写行情事实，响应和 Worker 结果明确 `automatic_assumptions=false`、`automatic_valuation=false`、`automatic_rating=false`；不会因为取得价格而生成预测、估值、评级或概率。
- “基本面与预测”页面可显式同步并读取最近复权价格，展示价格观测 ID，供人工填写的研究输入引用。财务事实模板仍不自动把价格写入审批内容，分析师必须确认价格时点与证据适用性。
- PostgreSQL 隔离回归覆盖真实适配器形状、复权价优先、来源 URL 去凭据、首次可获得时间、重复同步幂等，以及没有预测/评级副作用；生产验收需要对样板标的同步并读回非零不可变价格观测。
